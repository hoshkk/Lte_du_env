# RX 점검 (Android) — RTL-SDR V4 장비 리버스 / 불요파

휴대폰 OTG에 RTL-SDR Blog V4를 연결해 KT LTE 기지국 RX(상향) 대역을 현장에서 점검하는 앱입니다.
드라이버부터 처음부터 작성했고 C/NDK 없이 Kotlin만 사용합니다.

## 측정 모드

| 모드 | 용도 | 결과 |
|---|---|---|
| **장비 리버스** | 장비 RX 경로(커플러·모니터 포트)의 상향 잡음·간섭 | 채널 전력, PSD(dB/MHz), **1 MHz 블록별 PSD**(블록 중앙값 대비 차이), **기준 대비 변화**(조용한 시간대에 저장한 기준과 비교) |
| **불요파** | 안테나 쪽 RX 대역 주변 불요 발사 | 노이즈 플로어, 플로어+임계 이상 피크 목록(주파수/레벨/폭/RX 대역 내외), Max Hold |

대역 프리셋 (RX 센터는 현장 확인값, 사이트별 확인 필요):

| 프리셋 | 채널 | 장비 리버스 Span | 불요파 범위 |
|---|---|---|---|
| B8 RX | 909.3 MHz / 10 MHz | 15 MHz | 894.3–924.3 MHz (B8 DL 925 MHz 직전까지) |
| B3 RX 20M | 1745.0 MHz / 20 MHz | 25 MHz | 1725–1765 MHz |
| B3 RX 30M | 1750.0 MHz / 30 MHz | 31 MHz | 1720–1766 MHz (V4 상한) |

## 화면 조작 (SpectrumCheck 2.7.1과 같은 방식)

| 조작 | 동작 |
|---|---|
| 그래프 탭 | 선택한 마커(M1~M5)를 그 주파수에 놓기 |
| 한 손가락 위아래 드래그 | Ref Level 이동 (측정은 계속) |
| 두 손가락 핀치 | Span 확대/축소 (Center 고정, 손을 뗄 때 적용) |
| Peak / Clear | 선택 마커를 최대 피크로 / 해제 |
| Gain − / ＋ | 수동 이득 0~15 단계 |
| 자동 맞춤 | 클리핑이면 이득을 한 단계씩(최대 3번) 낮추고, 아니면 Ref·dB/div를 화면에 맞춤. 이득을 올리지는 않음 |
| 빠른 설정 저장/관리 | 모드별로 현재 설정 저장·불러오기 (재실행 후 유지) |
| CSV 저장 / 공유 | 파일로 저장하거나 카톡 등으로 바로 공유 |

- Span 2 MHz 이하(1구간)는 재동조 없이 연속 수신해서 가장 빠르게 갱신됩니다.
- 입력이 ADC 끝까지 차면(0.1% 이상) **클리핑 경고**가 빨간 글씨로 표시되고, 그 스윕은 기준으로 저장할 수 없습니다.
- USB가 잠깐 끊기면 최대 5번 자동 재연결합니다. 앱을 벗어나면 측정을 멈추고 동글을 놓아줍니다.

## 정확도를 위해 한 것

- **좁은 IF 필터(기본)**: librtlsdr와 같은 방식으로 2.4 MS/s에 맞춘 약 2.4 MHz IF 필터를 씁니다. B8 RX 바로 옆 DL처럼 강한 인접 신호에 의한 동글 포화를 줄입니다. librtlsdr 원본 C 함수로 만든 값과 13개 샘플레이트에서 일치하는지 테스트합니다.
- **FFT 평균**: 구간마다 여러 장을 평균해 같은 잡음의 출렁임이 ±1 dB 수준입니다(1장이면 ±5 dB 이상).
- **안정화 대기(선택)**: PLL 잠금 후 0~100 ms 추가 대기. 기본 0, 기존 앱과 같게 보려면 10 ms.
- **기준 비교 조건**: Span·RBW뿐 아니라 이득·IF 필터·DC 설정까지 같을 때만 기준과 비교합니다.

## 속도를 위해 한 것

스윕 시간의 대부분은 구간마다 튜너를 옮기는 USB 제어 전송입니다(휴대폰에서 1회 약 2 ms).
이 앱은 구간 이동 시 전송 수를 줄였습니다.

| | 일반 드라이버 순서 | 이 앱 (고속 동조) |
|---|---|---|
| I2C 리피터 열기/닫기 | 매 이동 4회 | 0회 (계속 열어 둠) |
| PLL 레지스터 0x14–0x16 | 3회 | 1회 (I2C 버스트) |
| 값이 같은 레지스터(VCO 전류, 분주비, mux) | 매번 전송 | 생략 |
| 고정 대기(sleep) | 10 ms | 기본 없음 (PLL 잠금 확인 후 FIFO 리셋 + 2048샘플 폐기), 설정으로 추가 가능 |
| **구간당 제어 전송** | 13–15회 | **약 9회** (동조 7 + FIFO 리셋 2) |

- 기록되는 값(주파수, PLL 설정, 잠금 확인)은 일반 순서와 같습니다. 단위 테스트가 두 방식의 최종 튜너 레지스터가 동일한지 비교합니다.
- 설정의 **고속 동조**를 끄면 참고 드라이버와 같은 순서로 동작합니다. 현장에서 A/B로 비교할 수 있습니다.
- 화면 하단에 스윕 시간, 구간당 USB 제어 횟수가 표시됩니다.

또 구간마다 FFT를 여러 장 평균(기본 장비 리버스 16, 불요파 4)해서 트레이스가 잔디처럼 튀지 않습니다.
평균 1장은 0.1 ms 수준이라 속도에 거의 영향이 없습니다.

## 설치

1. GitHub → Actions → **Android APK** → 최신 실행 → `rx-check-debug-apk` 다운로드
2. 압축 해제 후 `app-debug.apk` 설치 (출처를 알 수 없는 앱 허용 필요)
   - 디버그 빌드는 빌드마다 서명이 달라, 업데이트 시 기존 앱 삭제 후 설치해야 할 수 있습니다.
3. 동글 연결 → 앱 실행 → **측정 시작** → USB 권한 허용

동글 없이 **데모** 버튼으로 화면을 먼저 볼 수 있습니다(시뮬레이터).

## 사용 순서 (장비 리버스)

1. 모드 **장비 리버스**, 대역 프리셋 선택, 이득을 낮게(기본 2/15)
2. 트래픽이 적은 시간에 측정 → **현재를 기준으로 저장**
3. 문제 시간대 측정 → 채널 전체 상승(dB)과 상승한 1 MHz 블록 확인
4. 커플러 손실 등을 알면 **Offset**에 입력 (표시값만 보정, 교정 dBm 아님)

기준은 Span·RBW가 같은 측정에만 적용됩니다(다르면 자동으로 무시).

## 한계

- 레벨은 dBFS 상대값입니다. 전파법 적합성 판정용 측정기가 아닙니다.

### 1.4.0 측정 원칙 (신호를 숨기지 않음)

- 앱은 정상·불량·불요파 유무를 **판정하지 않습니다**. 결과 카드는 측정 유효성(측정 완료 / 미측정 구간 있음 / 입력 과다 등)과 수치만 보여줍니다.
- 28.8 MHz 배수, 무입력 기록과 같은 주파수, 구간 중심(DC) 위치의 피크는 **표시만** 하고 제외하지 않습니다. 채널 전력은 원본 스펙트럼으로 계산합니다. '동글 신호 보정값'은 설정에서 켰을 때만 별도 줄로 나옵니다.
- DC 처리(I/Q 평균 제거, 중심 3 bin 보간)는 기본으로 꺼져 있습니다. 'DC 위치' 피크는 메뉴 → **중심 이동**으로 다시 측정해, 남으면 실제 신호, 사라지면 수신기 DC로 구분합니다.
- PLL 잠금 실패 등으로 채널(또는 블록, 기준) 안에 미측정 bin이 있으면 채널 전력·블록 PSD·기준 대비 값은 **미측정**으로 표시하고 계산하지 않습니다. 그래프에는 주황 빗금, CSV에는 `UNMEASURED`로 남습니다.
- 불요파 목록은 이번 스윕에서만 보인 피크, Max Hold에만 남은 피크, 평균에 묻히는 짧은 신호(프레임 최대값)까지 모두 보여주고 '반복 n회 / 이번 스윕만 / Max Hold / 짧은 신호'로 구분합니다.
- 8-bit 동글이라 동시 다이나믹레인지가 약 45 dB입니다. 강한 신호 옆의 아주 낮은 불요파는 동글 자체 왜곡일 수 있습니다.
  이득을 낮춰도 dBc가 그대로인지 확인하세요.
- 수신 범위 24–1766 MHz (V4). B3 DL, 2.1 GHz, 3.5 GHz는 측정할 수 없습니다.
- 실제 하드웨어 검증 전입니다. 단위 테스트는 레지스터 모형(fake USB)과 시뮬레이터로 동작을 확인한 것입니다.

```
android/
  core/   순수 Kotlin (JVM 테스트 가능)
    rtl/       RTL2832U + R820T/R828D(V4) 드라이버, USB 제어 계층
    dsp/       FFT, 평균 파워 스펙트럼
    sweep/     스윕 계획(구간 75% 사용), 스윕 엔진
    analysis/  채널 전력, 블록 PSD, 피크 검출, 측정 유효성 표시
    sim/       데모/테스트용 시뮬레이터
```

드라이버 레지스터 값과 초기화 순서는 Apache-2.0 라이선스의 webrtlsdr를, IF 필터 선택은 GPL 라이선스의 librtlsdr를 참고했습니다. [THIRD_PARTY.md](THIRD_PARTY.md) 참고.

### 1.5.0 현장 도구

- **확대(실시간)**: 그래프를 길게 눌렀다 떼면 그 근처 가장 높은 점을 중심으로 약 0.8–0.9 MHz를 한 번에 수신(재동조 없음, DC는 화면 밖). 하단 "◀ 전체로"로 복귀.
- **근접 탐색 소리**: 시작 대비 레벨이 오를수록 삐 소리가 빨라짐(+20 dB에서 초당 약 16회). 표시창의 "소리 켬/끔".
- **워터폴**: 하단 "워터폴" 토글. 최근 최대 200회 스윕, 위가 최신, 색 범위는 그래프 Ref·dB/div와 같음. 미측정은 갈색.
- **자가점검 · 속도 진단** (메뉴): 마지막 스윕의 구간당 튜닝/수집/계산 시간, PLL 잠금·샘플 속도·ADC·Gain 반응 점검, 주파수 전환 후 안정 시간 측정(측정만 하고 설정은 바꾸지 않음).


### 1.10.0 자동 주파수 보정 (LTE)

- 메뉴 "자동 주파수 보정 (LTE B8 하향 신호)": KT B8 하향 954.3 MHz 캐리어의 동기 신호(PSS)를 찾아 동글 수정 오차(ppm)를 재고 설정에 바로 적용. 측정 중에만, 약 1초.
- 방식: 순환 전치(CP) 위상으로 15 kHz 이하 오차, PSS(Zadoff-Chu 25/29/34) 상관으로 15 kHz 단위와 LTE 여부 확인(5 ms마다 5번 중 3번 이상 반복해야 인정), PSS 타이밍으로 CP 구간만 다시 계산해 정밀화. 캐리어가 100 kHz 래스터 위에 있다는 점으로 ±50 ppm 안의 오차를 정함.
- 1766 MHz 넘는 하모닉 구간(B3 하향)은 기준으로 쓸 수 없음. B8로 맞춘 값은 동글 전체에 적용됨.
- 합성 LTE 신호 시험: 신호가 잡음보다 3 dB 약해도 오차 0.3 ppm 이내.
